# CONTENT.md — как устроен учебный контент физики

## 1. Формат экзамена (сверено с источником, не унаследовано)

| Параметр | Значение | Источник |
|---|---|---|
| Часть A | 10 заданий с выбором одного ответа из пяти | перечень РИКЗ (ЦЭ/ЦТ/РЦЭ 2025), физика: 10 · 20 · 30 · 210 |
| Часть B | 20 заданий с кратким ответом (число, величина с единицей) | там же |
| Время | 210 минут | там же |
| Проверено | 2026-10-14 | `content_src/periods.py` (константа `SOURCE`) |

Математические 18A+12B и 180 минут **не используются**: это другой предмет.
Рекламные материалы «180 минут для физики» считаются недостоверными (в 2025 году
такое время было у языков/биологии; на репетиционном тестировании РТ структура
тоже иная — 18A+14B). Любое изменение формата — только вместе с новой ссылкой и
датой в `periods.py` и в этой таблице.

## 2. Что такое авторские варианты (и чем они не являются)

* Шесть вариантов `2021…2026`, в каждом 10 заданий части A и 20 части B.
* Формулировки, числа и разборы написаны автором по программе ЦТ. Это **не**
  официальные материалы РИКЗ, и ни один экран не должен утверждать обратное.
* Дисклеймер живёт в `content_src/periods.py` (`DISCLAIMER`), попадает в
  `version.json` (ключ `disclosure`) и показывается в «О программе».
* Задания нельзя «добивать числом»: качество проверяется структурой
  (смотри §5) и требованием уникальности ответов в части A.

## 3. 13 областей программы (покрытие проверяется сборкой)

1. измерения, СИ, приставки, размерность, погрешность (`measurements`)
2. кинематика: путь/перемещение, скорость/ускорение, свободное падение (`kinematics`)
3. динамика: законы Ньютона, силы, трение, упругость, диаграмма сил (`dynamics`)
4. работа, мощность, энергия, импульс (`workenergy`)
5. статика, момент, давление, гидростатика (`statics`)
6. молекулярная физика, количество вещества, газовые законы (`molecular`)
7. теплота, теплоёмкость, фазовые переходы, первое начало (`thermo`)
8. электростатика: закон Кулона, поле, потенциал (`electrostatics`)
9. постоянный ток: закон Ома, соединения, работа и мощность тока (`current`)
10. магнитное поле: силы Ампера и Лоренца, индукция (`magnetism`)
11. колебания, волны, звук (`oscillations`)
12. оптика: отражение, преломление, линзы (`optics`)
13. квантовые явления, атом, ядро, радиоактивность (`quantum`)

`tools/build_content.py` падает, если тема не встречается одновременно в варианте
и среди аналогичных заданий, а `content_src/study.py` обязан иметь конспект для
каждой темы (иначе после неверного ответа ученику нечего открыть).

## 4. Контракт проверки ответа (физика, а не математика)

Спецификация задания, которая уезжает в приложения (`spec` в JSON):

```json
{
  "answerType": "choice | number | quantity",
  "answerValue": "10",                        // точное значение в единице unit
  "unit": "м/с",                              // единица, в которой ждут ответ
  "unitPolicy": "named | optional | required",// требует ли поле единицу
  "dimension": "m/s",                         // подпись размерности ответа
  "tolerance": {"kind": "absolute|relative", "value": "0.5"},
  "rounding": 2                               // допуск по границе округления
}
```

Правила, которые обязаны соблюдать Python, JavaScript и Kotlin (одни и те же
векторы в `dist/content/answer_vectors.json`):

* запись ответа: `10`, `10,5`, `10.5`, `-3`, `1e-3`, `1,5·10⁻³`, `3·10⁵`;
  пробелы-разделители разрядов (`1 000`) допустимы;
* если ученик написал единицу, она разбирается по **белому списку** и переводится
  в СИ: `36 км/ч` = `10 м/с` — верно; `10 см` вместо `10 м` — неверно;
  `10 Н` вместо `10 кг` — неверно с причиной `dimension`;
* °C — единственная единица со смещением: `27 °C` = `300,15 К`; в данных заданий
  °C запрещён (только кельвины), в ответе ученика допустим там, где это осмысленно;
* `unitPolicy: required` — ответ без единицы не принимается (`missing_unit`);
* допуск задаёт само задание: либо `tolerance`, либо `rounding` (полуширина
  половины последнего разряда), иначе абсолютный `1e-9`;
* никакого `eval`: выражения формул разбираются собственным парсером с белым
  списком символов и целыми показателями степеней.

## 5. Как устроены модули (`content_src/`)

| Файл | Роль | Ключевые проверки |
|---|---|---|
| `quantities.py` | единицы, размерности, парсер чисел, `check_answer`, парсер моделей | белый список единиц, приставки, °C-смещение, точные дроби |
| `kit.py` | авторские конструкторы заданий, векторы ответов | размерность формулы, единицы данных/ответа, домены, подстановки `{symbol}`, объяснения дистракторов |
| `variants.py` | движок вариантов 2022–2026 | дистрактор из неверной модели; совпадение с верным ответом — ошибка сборки |
| `task_bank_2021.py` | вариант 2021 года, написан руками | то же |
| `task_bank_2022…2026.py` | обёртки над `variants.build(year)` | состав 10A+20B из `periods.py` |
| `templates.py` | 39 аналогичных заданий, детерминированный seed | покрытие 13 тем, уникальность id |
| `theory.py` | 37 уроков: определение, условия, пример, «бытовое» + границы модели | двуязычность и параллельность абзацев, только существующие схемы |
| `diagrams.py` | 26 схем: типизированный SVG 420×280 | допустимые примитивы и роли, границы координат, непустые подписи |
| `formulas.py` | 13 групп формул со ссылками на уроки | каждая строка ссылается на урок своей группы |
| `study.py` | 13 конспектов «что изучить после ошибки» | ссылки на уроки и группы формул, длина пунктов |
| `mistakes.py` | 52 тега типичных ошибок + чек-лист самопроверки | каждый тег задания обязан быть описан здесь |
| `ui_strings.py` | 213 надписей RU/EN | ключи интерфейса, совпадение числа `%s` в ru/en |
| `periods.py` | структура варианта, дисклеймер, источник | 10A+20B, 210 минут, ссылка на перечень РИКЗ |

## 6. Чего в контенте быть не должно

* Математических заданий, формул и «математического» языка в текстах (сборка
  ищет слова-маркеры чужого предмета).
* Схем с «сырым» SVG, внешними библиотеками, CDN или `eval` — только
  типизированные примитивы из `diagrams.py` и просмотрщик приложения.
* Графиков, которые противоречат закону: у каждой схемы есть словарь `model`
  (например `inverseSquare`, `floatCondition`), по которому сборка/тесты
  проверяют физический смысл, а не только картинку.
* Утверждений, что модель верна всегда: у урока про свободное падение должно быть
  сказано про сопротивление воздуха, у газовых законов — про идеальный газ,
  у тепловых расчётов — про потери и КПД.

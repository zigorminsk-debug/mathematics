# Ключ подписи физики (`android/keystore/`)

Здесь лежит **постоянная** подпись Android-приложения «Репетитор ЦТ: Физика»
(`by.ziv.ctphysics`). Она зафиксирована до первого выпуска: после публикации
первого APK пакет и сертификат менять нельзя, иначе обновление не установится
поверх установленного приложения.

| Файл | Назначение |
|---|---|
| `ctphysics-release.p12` | PKCS#12-хранилище release-подписи (alias `ctphysics`) |
| `keystore.properties` | путь/alias/пароли для Gradle (`storeFile`, `storePassword`, `keyAlias`, `keyPassword`) |
| `expected-cert-sha256.txt` | SHA-256 отпечаток сертификата, который сверяет CI |

Отпечаток сертификата:

```
A3:55:CB:12:F5:22:E9:A7:F6:FE:E3:A6:6C:E9:15:1D:73:23:40:58:A9:85:FA:57:19:CD:28:3E:63:21:35:83
```

## Как это проверяется

```bash
python3 tools/check_signature.py --require \
  --keystore android/keystore/ctphysics-release.p12
```

В CI тот же инструмент запускается перед сборкой и по собранному APK:

```bash
python3 tools/check_signature.py --require \
  --apk android/app/build/outputs/apk/release/app-release.apk \
  --tool "$ANDROID_HOME/build-tools/34.0.0/apksigner"
```

## Правила

1. **Не менять ключ.** Ротация только вместе с новым пакетом (например
   `by.ziv.ctphysics2`) и явным решением пользователя; иначе обновление сломается.
2. **Не хранить пароли в чате.** Секреты передаются через секреты CI
   (`ANDROID_KEYSTORE_FILE`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`,
   `ANDROID_KEY_PASSWORD`); файл `keystore.properties` содержит локальные значения
   и не должен попадать в чужие ветки.
3. **Математический ключ не переиспользуется.** У математики свой файл
   (`ctmaths-release.p12`) и свой отпечаток `B2:BD:…:65`; физика не может быть
   подписана математическим сертификатом — это прямо запрещено контрактом
   изоляции (см. `docs/RELEASE.md`).
4. **Debug-подпись не публикуется.** В релиз попадает только release-APK,
   переименованный в `phyzics.apk`; `app-debug.apk` остаётся артефактом
   разработки и использует отдельный пакет `by.ziv.ctphysics.debug`.

## Если ключ потерян

Публикация обновлений «поверх» становится невозможной: пользователям придётся
ставить приложение заново. Поэтому перед первым релизом файл дублируют в
защищённом хранилище (внешний сейф/менеджер секретов). В репозитории хранится
только текущая копия и отпечаток.
